# 话题元素材采集工作流 (Topic Materials Compilation)

> **用途**：当用户需要为某个特定话题（如即将创作的内容、B站深度视频、小红书系列等）准备补充素材时，从现有日/周报档案中"挖掘"相关热点，而非启动新的全量采集。
> **与日报/周报的区别**：日报/周报是"从互联网采集新信号"；话题元素材采集是"从已有报告库中提取相关条目 + 标注关联 + 整合分析"。
> **报告目录**：`~/Desktop/qoder_workspace/hermes_workspace_tmp/reports/hotspot-research_qoder/`

---

## 触发条件

当用户请求满足以下任一特征时，使用此工作流：

- "从过去N天的热点中，精选与XXX话题相关的信息"
- "结合近期采集的热点，为XXX话题补充元素材"
- "回顾XXX天的日报，找到关于XXX的强相关条目"
- 明确提到"元素材储备"、"补充素材"、"话题准备"等关键词
- 用户举出具体案例来完善话题论证（如"公司配AI但没人用""Token当KPI员工刷"），需要从报告库验证是否存在

---

## 工作流（5步骤，含补采模式）

### Step 1：定位核心信息 + 确定搜索范围

1. 使用 `Grep` 搜索最近相关的日报文件
2. 使用 `Glob` 列出目标时间范围内的所有日报文件
   ```
   Glob pattern="report_daily_*.md" path="~/Desktop/qoder_workspace/hermes_workspace_tmp/reports/hotspot-research_qoder/"
   ```
3. 使用 `Read` 读取核心日报（通常是最近一期的日报），提取核心事件
4. 确定搜索关键词（中文+英文混合）

### Step 2：双层搜索——先报告库，后外部补采

**第一层：报告库内搜索**

使用多种方式交叉搜索日报MD文件：

1. `Grep` 针对目标文件搜索英文关键词（如 `psycho`）——逐文件精准命中
2. `Grep` 批量搜索中文关键词（注意输出可能被截断，可分批搜索）
3. 搜索 AI HOT JSON 原始数据（如存在 `aihot_daily_YYYY-MM-DD.json`）——包含日报未收录的条目

**⚠️ 中文搜索的已知限制**：
- `Grep` 对中文字符+正则组合的跨文件搜索可能不稳定，窄模式（如单关键词）比宽正则可靠
- 批量搜索大量报告时输出可能被截断——解决方案：分批运行，或限定目标文件范围

**第二层：外部补采（仅当用户提到的案例在报告库中确认不存在时）**

触发条件：用户明确提到具体案例，但经过以下穷举搜索后仍无匹配：
- 全部日报MD文件全文搜索 ✓
- AI HOT JSON原始数据搜索 ✓
- 周报搜索 ✓

补采流程：
1. 告知用户"这N个案例日报中确实没有收录——原因是采集系统同期遗漏"
2. 使用 `WebSearch` 搜索关键词
3. 用 `WebFetch` 或 Jina Reader (`r.jina.ai/{url}`) 提取全文
4. 标注为 "🆕 日报遗漏补采" 并注明替代来源
5. 写入文档时在来源索引表中标注"日报遗漏，补充采集（来源）"

**补采来源优先级**：36氪中文报道（eu.36kr.com）> Financial Times/WSJ > Tom's Hardware/Ars Technica > 其他技术媒体

### Step 3：精选 + 分级 + 关联矩阵

对搜索结果进行三轮筛选：

1. **去重**：同一事件在多份日报中重复出现 → 保留覆盖最完整的一期
2. **分级**：
   - 🔴 P0：与核心话题有直接因果/对比/伏笔关系
   - 🟡 P1：有方法论层/认知层关联
   - ⚪ P2：有数据或背景补充价值
3. **关联矩阵**：每个精选话题标注"与核心话题的关联强度"+"逻辑层级定位"

### Step 4：整合输出（SOUL 四视角 + 关联矩阵）

输出格式见下方模板。核心结构：
- 核心信息摘要表
- N个补充话题（每个含维度表 + SOUL叙事建议 + 受众共鸣点）
- 关联矩阵（ASCII图）
- SOUL 四视角整合分析
- 三平台分发方案
- 素材来源索引

## 每个补充话题的标准维度表

```markdown
### 话题N：[标题]

| 维度 | 详情 |
|------|------|
| **日期** | 原始信息日期（含日报覆盖日期） |
| **来源** | 原始来源 + 日报文件 |
| **核心数据/观点** | 2-3句摘要 |
| **信息完整度** | 100%/80%/60%/30% |
| **与核心话题的关联** | 🔴/🟡/⚪ + 一句话关联逻辑 |
| **SOUL叙事建议** | 反常识钩子一句话 |
| **受众共鸣点** | 受众画像 + 情感触发 |

**详细背景**：(2-3段，展开核心观点和上下文)

**对核心话题的增强**：(1-2段，解释这个话题如何补充/解构/质疑核心事件)
```

## ⚠️ 常见陷阱

1. **不要对每条补充话题做完整的四视角分析**——那太重了。四视角整合放在文档末尾，做整体分析。
2. **补充话题数量以论证强度为准**——典型范围5-10个。按照内容性质分两层：
   - **理性论证层**（5个左右）：数据、方法论、个体行动、机构伏笔、现实对账
   - **荒诞行为层**（3-5个）：决策层荒诞（AI精神病）、成本层荒诞（烧钱失控）、生态层荒诞（一边卖一边撤）、KPI层荒诞（刷Token游戏）、结构层荒诞（AI精英阶级分化）
   分层并非硬性约束——关键在于每种话题必须有独特论证角度。
3. **优先选有时间线逻辑的话题**——有"前兆→核心→验证"的时间线比孤立话题有价值得多。
4. **优先选"荒诞/矛盾性质"的内容**——自带矛盾的素材叙事张力天然比纯数据强。
5. **每个话题要标注信息完整度**——100%（全文提取）> 80%（多源交叉）> 60%（单源摘要）。
6. **补采话题必须与核心话题有时序关联**——只补充与核心事件在同一报道窗口（±7天）内的遗漏素材。
7. **文档写入使用 `Write` 工具**——不要使用 Bash heredoc（`&` 字符会触发后台进程检测）。
8. **如果用户说"这些在日报里提到过"但搜索不到**：先穷举确认（MD+JSON+周报），再透明告知，最后补采。不要擅自下结论说"日报里没有"——先搜，搜不到再说。
