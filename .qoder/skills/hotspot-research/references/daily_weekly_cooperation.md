# 日报→周报协作机制

> **核心原则：** 日报是周报的输入，不是平行的产出。日报的分析成果必须流入周报。
> **报告目录：** `~/Documents/qoder_workspace/hotspot/reports/hotspot/hotspot-research_qoder/`

---

## 本周线索格式（日报末尾固定 section）

每份日报末尾必须包含此 section，供周报汇聚：

```markdown
## 📡 本周线索

> 以下线索供周报汇聚使用。每条线索是一个跨日可能发酵的主题。

| 线索ID | 主题词 | 今日信号 | 简要说明 |
|--------|--------|---------|---------|
| W-01 | {主题} | 🔴强 / 🟡中 / 🟢弱 | {一句话描述，含关键人名/事件名} |

_历史线索：{从本周已出日报中提取的跨日线索统计}_
```

---

## 线索ID 规则

- 格式：`W-{周数}-{两位序号}`（如 W-25-01, W-25-02, ...）
- 同一主题在不同日报中必须使用**相同线索ID**
- 通过标题关键词 Jaccard 相似度 > 0.5 判定为同一主题
- 新出现的主题分配下一个可用 ID
- 报告发布前必须读取 `_week_clues.json`（如不存在则创建空文件）
- 新增线索追加到末尾并写回；过期（>30 天无信号）的线索标记为 `[EXPIRED]` 归档

---

## 信号强度定义

| 信号 | 条件 |
|------|------|
| 🔴强 | P0 标签 + 有新数据点/新角度 |
| 🟡中 | P1 标签 或 P0 但无新角度 |
| 🟢弱 | P2 但可能发酵 |

---

## 周报汇聚逻辑

```
Step 0（新增）：读本周所有日报的「📡 本周线索」section
    ↓
统计每条线索的跨日出现情况：
  ├─ 连续 ≥ 3 天 → 强信号，必入周报 Top 5 主题
  ├─ 累计 ≥ 2 天 → 中信号，讨论是否纳入
  └─ 仅 1 天 → 弱信号，仅如果非常重磅才纳入
    ↓
识别 #1 主题（连续天数最多 + 信号强度最高 → 横纵分析对象）
    ↓
Step 0-7 执行时优先围绕已识别的主题采集补充信息
```

---

## 数据依赖

```
周报读取日报的方式：
  使用 Grep 搜索本周日报的「📡 本周线索」section
  不读日报全文（避免 token 爆炸：7×350行 ≈ 无法承受）
  日报全文仅在需要引用具体分析时用 Read 按需加载
```

---

## 容缺策略

| 日报缺失天数 | 处理 |
|-------------|------|
| 0 天 | 正常汇聚 |
| 1-2 天 | 标注"本周线索不完整（缺 X 天）"，仍可汇聚 |
| ≥ 3 天 | 标注"本周线索严重不完整"，退回旧模式（从零扫描） |

---

## 与 AI HOT 的交叉验证

```
日报线索 → 周报汇聚主题列表
AI HOT volume signal → 本周出现频次最高的 AI 行业关键词
    ↓ 交叉
如果某主题同时出现在日报线索（跨日出现）和 AI HOT（高频出现）中
  → 确认为 #1 主题（双源验证，置信度最高）
如果某主题仅出现在日报线索
  → 可能是"AI对个体的影响"相关（AI HOT 不覆盖此方向）
如果某主题仅出现在 AI HOT
  → 可能是"纯AI技术/行业"事件，需人工判断 SOUL 相关性
```

## 文件搜索方式

使用 Qoder 的 `Grep` 工具搜索历史报告：

```
# 搜索本周所有日报的线索 section
Grep pattern="## 📡 本周线索" path="~/Documents/qoder_workspace/hotspot/reports/hotspot/hotspot-research_qoder/" glob="report_daily_*.md"

# 搜索特定关键词
Grep pattern="某个主题词" path="~/Documents/qoder_workspace/hotspot/reports/hotspot/hotspot-research_qoder/" glob="report_daily_*.md"
```
