# 理论渗入诊断：赵汀阳思想如何进入采集报告

> 日期：2026-07-07 | 来源：卷哥提问 "定位每日采集任务为什么会受到赵汀阳思想的影响"

---

## 一、症状

每日热点采集报告（日报/周报）和话题素材深挖报告中，出现赵汀阳哲学概念的署名引用，如：
- 选题标题直接写 "赵汀阳 correlate 实证"
- 深度分析步骤写 "连接SOUL：赵汀阳correlate vs understand"
- 八层恐惧分析第5/6/8层固定使用赵汀阳理论
- 五结构归因第5项固定为 "Token源头转移（赵汀阳）"

---

## 二、根因：三条渗入路径

### 路径① System Prompt 直接注入（主要路径）

SOUL 身份是 Hermes 的 system prompt，包含完整的赵汀阳知识图谱。**每个 cron session 的 LLM 都带着这个 system prompt 启动**，即使没有显式加载 soul skill。

当 LLM 处理热点话题时，从 system prompt 中提取赵汀阳概念作为分析框架。

### 路径② 报告模板 "SOUL 框架赋能" 标记

`templates/report_template.md` 顶部标注 "SOUL 框架赋能"，深度分析段有 "SOUL 框架关联" 字段。
这些标记引导 LLM 在生成报告时主动调用 SOUL 框架（=赵汀阳概念）。

### 路径③ creator_profile "哲学思考者" 人设标签

`references/creator_profile.md` 定义 "核心身份：现代哲学思考者"。
"哲学思考者" 标签激活 LLM 从 system prompt 的 SOUL 知识图谱中提取赵汀阳概念。

**修改**：

**被否决原因**（卷哥）：

问题：
1. 删除了 "现代哲学思考者" 标签——这是卷哥的差异化定位

3. 没有先汇报分析结果就动手

## 五、第二次修复（v2 · 当前版本）

**思路**：标注透明化——让框架的来源和边界可见，而非删除框架。

**修改**：
- `creator_profile.md`：恢复 "现代哲学思考者" 标签（完全回退 v1 修改）
- `calibration_checklist.md`：F 类从 "理论偏向检查（删除）" 改为 "框架来源透明性（标注）"
  - 框架溯源标注：使用结构归因/八层恐惧时在末尾标注来源
  - 事实层与框架层分离：事实校准段用中立描述，框架分析段才用理论
  - 跨话题框架多样性：避免所有报告收束到同一理论家
- `report_template.md`：保留 v1 中 "SOUL 框架赋能→多维度信息聚合" 的中性化修改
- `hotspot-topic-excavator/SKILL.md`：执行原则从 "理论中立性" 改为保持 F 类校准流程

**核心原则**（已写入 SOUL skill 第 7 条对话原则）：
> **修改用标注，不用删除** — 标注框架来源 > 删除框架引用 > 保留人设标签 > 删除标签

## 六、教训

1. **"适当解除"≠删除**：卷哥说的 "适当解除影响" 意味着让影响**可被看见和管理**，不是让影响**消失**。赵汀阳是 SOUL 的核心锚点，他的渗入不是 bug，是框架必然会呈现的特征。

2. **分析先于行动**：先完成诊断报告，让卷哥看到完整图景，再商量方案。不要自己决定 "什么该删"。

3. **黑名单是最后的选项**：标注透明化 → 适用范围约束 → 多样性要求 → 黑名单删除。每一步都是更轻的干预。

4. **用户的标签是用户的财产**：不要删除用户定义的身份标签（如 "现代哲学思考者"），那是用户定位的一部分。
