# 案例型话题深度挖掘方法论

> **来源**：2026-06-27 Pieter Levels 案例（创作者经济 2026：从影响力到基础设施）
> **问题诊断**：日报自动推荐 TOP 3 漏选 P0 极高关联度的案例型话题
> **根因**：现有排序权重偏向「事件型」话题，系统性压制「案例型/人物型」话题

---

## 一、案例型 vs 事件型话题的差异

| 维度 | 事件型话题 | 案例型/人物型话题 |
|------|-----------|------------------|
| 典型代表 | GPT-5.6 发布、AI 基础设施 7000 亿 | Pieter Levels、Notion 创始人、某独立开发者 |
| 信源数量 | 多平台同时报道（4-10 源） | 单一深度报道（1-2 源） |
| 本周线索连接 | 2-3 条线索 | 1 条线索 |
| 信息完整度 | 80-100% | 50-70% |
| **现有推荐得分** | **高分** | **被压制** |
| **实际内容生产价值** | 中-高（依赖标题吸引） | **极高**（依赖深度案例） |

---

## 二、自动推荐算法的隐藏权重（推断）

```
排序权重：
  信源交叉验证数量     ████████░░  40%  ← 多源命中 = 高置信度 = 优先
  本周线索连接数       ██████░░░░  30%  ← 连接越多线索 = 越"热"
  信息完整度           ████░░░░░░  20%  ← 已有信息越多 = 越"值得深挖"
  赛道关联度           ██░░░░░░░░  10%  ← P0/极高 是准入门槛，不是排序因子
```

**核心问题**：赛道关联度权重仅 10%，且作为「准入门槛」而非「排序因子」——这意味着即使 P0「极高」关联度，案例型话题仍会被信源单一+线索少的现实拉低排名。

## 三、补充维度：「内容生产价值」

在现有算法外，显式加入「内容生产价值」评分：

| 子维度 | 权重建议 | 评分标准 |
|--------|---------|---------|
| **受众共鸣强度** | 30% | 转型者 Marcus / 探索者 Lily / 觉醒者 Alex 的镜像程度 |
| **叙事完整度** | 25% | 是否有完整的人物弧线（起点→冲突→转折→结果） |
| **行动转化率** | 25% | 受众看完后是否知道「下一步具体做什么」 |
| **SOUL 框架适配** | 20% | 与控制性理念/通过仪式/三视角的契合度 |

**Pieter Levels 案例的「内容生产价值」得分**：
- 受众共鸣强度：9/10（Marcus 的完美镜像）
- 叙事完整度：10/10（10 年时间线 + 产品组合故事）
- 行动转化率：8/10（「从小产品开始」可复制）
- SOUL 框架适配：10/10（控制性理念完美案例论证）
- **总分：9.25/10**——远高于事件型话题的 6-7 分

## 四、判断启发式（何时手动触发）

当遇到以下任一情况，应主动手动触发本 skill 而不依赖自动推荐：

1. **赛道关联度 P0「极高」但没进推荐 TOP 3**——直接问"为什么没进"，然后手动触发
2. **信源 ≤ 2 源 + 线索 ≤ 2 条**——案例型话题的典型特征
3. **话题类型是"人物/案例"而非"事件"**——自然压制
4. **用户明确说"这个话题极高价值但没进推荐"**——必须挖掘

**操作流程**：
1. 用户问"为什么 X 没进推荐" → 展示算法偏差分析
2. 立即手动触发挖掘（不等待系统修复）
3. 挖掘完成后，回头建议系统算法优化（写入 _pending_review）

## 五、案例型话题的挖掘重点

与事件型话题相比，案例型话题需要额外关注：

### 必挖维度

| 维度 | 挖掘重点 | 工具/来源 |
|------|---------|----------|
| **完整时间线** | 起点→关键节点→当前状态 | Reddit 深度帖、官方博客、播客大纲 |
| **收入/数据拆解** | 精确数字 + 拆解到产品级 | X/Twitter 公开 MRR、第三方分析（如 SoftwareSeni、OneManDB） |
| **长深度对话** | 3 小时+ 访谈揭示内心世界 | Lex Fridman播客、Indie Hackers Podcast、Wannabe Entrepreneur |
| **金句提取** | 5-10 句可直接引用的原话 + 中文意译 | 播客转录、博客摘录 |
| **对立视角** | 幸存者偏差、可复制性争议 | GoldPenguin、Reddit r/SaaS 质疑帖、原作者自述 |
| **同类对比** | 同赛道其他代表人物 | Justin Welsh（数字产品）、Notion 创始人等 |
| **隐性成本** | 孤独、抑郁、错过的社交 | 播客中的"low points"章节、博客自述 |

### 必更新数据

如果第一轮挖掘后超过 1 周：
- 重新拉取 X/Twitter 最新数据
- 检查是否有新播客/采访发布
- 验证第三方分析的最新数字

## 六、案例型话题的内容产出模板

### 抖音 60-90s 脚本结构

```
0-5s:    Rupture - 用一个极端数据开场（如 $280K/月）
5-20s:   Illuminate - 起点故事（Google Sheet → 第一个产品）
20-40s:  Validate - 10 年时间线 + 收入拆解
40-60s:  Embody - "为什么这样做"（金句+原话）
60-80s:  Transform - 行动清单（受众能做什么）
80-90s:  金句收尾 - SOUL 框架
```

### 必须包含的"反常识钩子"

事件型话题的反常识钩子常是"原来 X 发生了"；
**案例型话题的反常识钩子常是"原来 Y 这样做的人成功了"**——打破受众的"必须这样"信念。

### 必须包含的"代价章节"

事件型话题常省略代价（因为事件本身是中性的）；
**案例型话题必须包含代价章节**（孤独、失败率、隐性成本），否则就是廉价的成功学。

## 七、迭代式深化的方法论

用户在第一轮挖掘后常会要求"进行一轮优化补充"——这是真实模式。

### v1 → v2 的标准补充清单

1. **长深度对话**（如 Lex Fridman Podcast #440 的完整大纲 + 5 句金句）
2. **最新收入数据**（X/Twitter 公开 MRR 拆解）
3. **同类对比数据更新**（如 Justin Welsh 最新累计收入）
4. **对立视角完整呈现**（幸存者偏差 + 原作者自述 + 反对者论点）
5. **5 维度对比框架**（替代单维度"反最佳实践"）
6. **AI 时代视角**（如 2026 年的特化版本）

### 工具使用模式

- v1: 4-5 个 brave_llm_context 并行 + 2-3 个 brave_web_search
- v2: 3-4 个补充搜索（针对 v1 不足的维度）
- 总工具调用 7-9 组，2 轮完成
