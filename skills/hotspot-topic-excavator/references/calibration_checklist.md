## 五类校准速查

### A. 事实校准（数字逻辑矛盾检查）

| 检查项 | 具体做法 | 常见陷阱 |
|--------|---------|---------|
| 子项不能大于总量 | 报告中出现"X含Y"且Y>X的表述 → 立即标记为逻辑矛盾 | "GAAP净亏损$385.3亿含$415.5亿非现金费用"（**不可能**：含项大于总量） |
| 同名机构多份报告区分 | 检查是否同一机构在不同时间/部门发布了多份文件 | Anthropic 6/16经济学论文 vs 2026初"Agentic Coding Trends Report"（产品侧PDF）——两篇不同文件，数据不能混用 |
| 多个损失口径不能混用 | 财务数据至少存在运营亏损/GAAP净亏损/调整后亏损三套口径 | OpenAI: $209.2亿(运营) ≠ $385.3亿(GAAP归属公司) ≠ $603.5亿(含非控股) ≠ ~$80亿(调整后) |
| 内部量化总结与原始附录对齐 | 报告中的"专家12次动作"等总结性数字——属于次级加工 | 标注"需与原始附录对齐"，列入"最优先补充动作" |

**关键教训**：
1. "含"字是危险信号——看到立即验算子集 < 总量
2. 财务数据出现"亏损"二字时，先问"哪个口径？"再写
3. 同名机构 = 同机构不一定同份报告，尤其Anthropic这种高频产出机构

### B. 事实补充（多源遗漏检查）

| 检查项 | 具体做法 | 常见陷阱 |
|--------|---------|---------|
| 大型调查报告的完整数据 | Adobe/Upwork等→不仅有主标题数据（"87%"），还有至少5-8个次级数据点 | 漏掉63%(信心)、40%(表现优势)、81%(判断不可替代)、90%(版权期望)、披露率、Agentic AI态度 |
| P1原文引用完整性 | 每个权威来源至少引用一处原文金句 | Fortune文章只取数字不引用分析逻辑 |
| 同一报告的多篇媒体报道 | 不同媒体突出不同数据点——用至少2家媒体交叉验证 | 9to5Mac取90%的Agentic数据而MarketScreener没取 |

### C. 表述校准（措辞精准度检查）

| 检查项 | 具体做法 | 常见陷阱 |
|--------|---------|---------|
| 批评的尺度 | "排除"→"限定"、"造假"→"错配"——批评性质不能放大 | AppleInsider指出"限定为social-first creators"→正确表述是"统计口径错配(scope mismatch)"，不是"数据造假" |
| 限定条件的明示 | 引用调查数据时，必须同时标注调查对象的限定条件 | "87%创作者"→应标注"被调查者限定为social-first creators" |
| "创作者"≠"所有创作者" | 行业术语有隐含限定 | Adobe的"creatives"≠传统创意产业全职从业者 |

### D. 框架补充（分析结构完整性检查）

| 检查项 | 具体做法 | 常见陷阱 |
|--------|---------|---------|
| 经济判断必查对冲变量 | "AI工具成本下降"→必须同时检查IPO/监管/竞争格局等反向压力 | OpenAI秘密提交IPO(目标$1万亿)→IPO后盈利压力可能推高定价 |
| 核心命题的"更深一层" | 每个核心论点问"还有什么被遗漏？" | "AI放大专业知识"→更深一层：Delegation Gap——不仅"你有没有判断力"，还有"你敢不敢委派" |
| 大方向成立 ≠ 路径是直线 | "长期趋势是X"≠"短期一定是X" | "AI工具成本下降"大方向成立，但路径上有IPO/企业盈利压力等非线性变量 |

### E. 对立视角（论证自反性检查）

| 检查项 | 具体做法 | 常见陷阱 |
|--------|---------|---------|
| 地域差异 | 全球报告→检查是否有单一国家/地区数据显著偏离均值 | Adobe印度数据：99%使用率/95%满意度 vs 全球平均87%——"AI吃掉自助书"在新兴市场未必成立 |
| 时间边界 | 趋势判断→检查数据窗口是否足够长 | "自助书暴跌"是基于Q1 2026数据——全年底可能反弹（季节性效应） |
| 社区反对声音 | 权威报告→查HN/Reddit/X上的批评和质疑 | Anthropic论文Reddit评价"比预期更有实质内容"（隐含期望"营销内容"） |
| 方法学质疑 | 调查→查是否有人指出了局限 | AppleInsider对Adobe的方法学批判 |

### F. 框架来源透明性（2026-07-07 新增 · 实验性）

> **目的不是禁用理论框架，而是让框架的来源和适用范围透明。**

| 检查项 | 具体做法 | 备注 |
|--------|---------|------|
| 框架溯源标注 | 报告中如使用结构归因/八层恐惧/三阶对话法等框架，**应在该节末尾标注「框架来源：SOUL/某理论家」**——让受众和未来的自己知道这是分析视角，不是客观事实 | 这是"标注"而非"删除"——理论框架是 SOUL 的合理工具，但要可追溯 |
| 事实层与框架层分离 | 报告的"事实校准"段（数据/数字/事件）应保持中立描述；"框架分析"段（八层恐惧/结构归因）才使用理论框架 | 两层不要混在同一段 |
| 跨话题框架多样性 | 如使用结构归因（如五结构归因），每份报告应至少在 2 个归因项上使用不同理论家——避免所有报告都收束到同一框架 | 防止"赵汀阳过载"——存在论层面 E 段用赵汀阳可以，但不能所有话题都用他 |

### G. 叙事引力（2026-07-08 新增 · JADEPUFFER 审查驱动）

> **定义**：某些话题自带情绪磁铁——AI 自主攻击、国家对抗、模型失控。报告容易顺着话题的"引力方向"夸大主张，而忽略结构性的对立事实。

| 高引力话题 | 引力方向 | 反引力锚（主动在主线中加入） |
|-----------|---------|--------------------------|
| AI 自主攻击 / "全球首例" | "AI 是灾难""史无前例""AI 替换了人" | 人类决策点数量；自主程度的精确定义；前例时间线；同期平行事件 |
| 国家技术对抗 | "零和博弈""军备竞赛" | 双方路线的互补性（如 360 智能体工程化 vs Anthropic 单模型暴力）；第三方独立分析的限制；"平行发展"替代"回应"叙事 |
| 模型失控 / 越狱 | "AI 已经失控" | 越狱成功率的具体数字（而非"被突破"的模糊表述）；厂商已部署的防护措施；"涌现性"vs"被预设"的区分 |

**自检问题**（报告出稿前对每类"高引力"话题必问）：
1. 报告中是否存在把"高度X"说成"完全X"的措辞？
2. 对立观点是在独立章节孤悬，还是被整合进了主线叙事？
3. 中国视角（如有）是"回应式"还是"平行式"？——"回应"=弱叙事，"平行"=强叙事。

### H. 受众工具链翻译（2026-07-08 新增 · JADEPUFFER 审查驱动）

> **定义**：安全报告/技术分析的原始建议是写给企业的。超级个体受众需要翻译成他们实际使用的工具名。

| 源材料语言 | 超级个体翻译 |
|-----------|------------|
| "升级 Langflow 到 1.3.0" | "检查你的 Langflow / Dify / Coze 版本——任何低代码 AI 编排工具都一样" |
| "改 Nacos 默认 JWT 密钥" | "如果你用微服务架构——检查 Nacos / Apollo / Consul 的默认凭据" |
| "MinIO 默认密码 minioadmin:minioadmin" | "所有自建对象存储——MinIO / 阿里云 OSS / 腾讯云 COS——检查是否用默认凭据" |
| "AI 凭证分级管理" | "OpenAI / Anthropic / DeepSeek / 通义 / 文心 的 API Key——按服务分开、设额度上限" |

**输出格式**：T-Transform 段分两部分——A. 工具链级自检表（8 行表格·工具名+检查项+原因）+ B. 通用 5 步行动清单。

### I. 三角叙事补洞（2026-07-08 新增 · JADEPUFFER 审查驱动）

> **定义**：大多数话题是两点叙事（A 发生→B 发生）。审查阶段问：有没有第三个点 C 能把叙事从线段变成三角形？

**操作**：
1. 检查话题是否在同期存在"中国平行发展"（政策/产业/学术）
2. 找到后：强关联层新增条目 → 时间线补入 → SOUL 框架表补充"中文受众的独特共鸣点"

**实证**：JADEPUFFER 话题从"Anthropic 预言→JADEPUFFER 兑现"的两点 → 加上"360 图龙锋 6/24 发布"后变成"Anthropic 预言→360 同日对标→JADEPUFFER 兑现"的三角。中文受众从"旁观者"变成"参与者"。

## 执行流程

```
报告初稿完成
    ↓
Step A: 逻辑扫描（3分钟）
    → 搜索"含"字→验算子集<总量
    → 搜索"亏损/利润/营收"→验证口径一致性
    → 搜索机构名→检查多份报告区分
    ↓
Step B: 完整性检查（2分钟）
    → 每个信号至少5个数据点？
    → 每个信号至少1处原话引用？
    → 每个报告至少2家媒体交叉？
    ↓
Step C: 措辞审计（2分钟）
    → 搜索"排除/造假/谎称"→降级为"限定/错配/不准确"
    → 搜索"创作者/用户/开发者"→检查限定条件
    ↓
Step D: 框架补洞（3分钟）
    → 每个经济判断→问"反向压力是什么？"
    → 每个核心命题→问"更深一层是什么？"
    → 每个趋势→问"路径是直线吗？"
    ↓
Step E: 对立补全（2分钟）
    → 查地域：有单一国家偏离吗？
    → 查时间：数据窗口够长吗？
    → 查社区：有人反对/质疑吗？
    → 查方法：调查对象有限定吗？
    ↓
Step F: 框架来源标注（1分钟·2026-07-07新增·实验性）
    → 检查结构归因/八层恐惧等分析框架→是否标注了框架来源？
    → 检查事实层与框架层是否在同一段混用？
    → 检查是否所有报告都收束到同一理论家？
    ↓
校准记录表嵌入报告末尾
    ↓
输出最终版
```
