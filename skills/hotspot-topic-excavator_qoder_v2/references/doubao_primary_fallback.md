# 中文搜索主源模式：WebSearch 不可用时的全信号采集方案

> **触发条件**（v2.6.2 · 2026-07-08 验证）
> - WebSearch 连续 ≥5 次失败
> - **且** WebFetch 也因网络/权限问题不可用
> - 此时中文关键词搜索从"Chinese supplement"升级为**全信号主采集源**
> **Qoder 工具适配版**：原 豆包 → WebSearch（中文关键词）；原 Brave → WebSearch（英文）

---

## 一、为什么中文搜索可以当主源

传统认知：中文搜索偏中文，英文覆盖弱。**实证推翻了这个假设。**

2026-07-08 Microsoft Frontier Company 深挖中，中文关键词搜索返回了：

| 信号类型 | 传统假设 | 实证结果 |
|---------|---------|---------|
| 微软英文公告 | "只有英文搜索能搜到" | 中文媒体转述（今日头条/AASTOCKS/中财网/新浪财经），信号完整 |
| AWS FDE 部门 | "英文源" | 中英文双语报道（新浪财经/东方财富/证券之星） |
| MIT NANDA 报告 | "学术源，中文搜不到" | 6 条不同媒体的完整转述（36氪/腾讯云/新浪新闻），核心数据无遗漏 |
| 中国制造业 | "中文搜索强项" | 美的/三一/嘉立创/比亚迪/美的泰国工厂全部命中 |
| 中美 AI 对比 | "需要英文源" | 中金研报/摩根士丹利/摩根大通全文转述，数据完整 |

**结论**：对于 AI/科技/商业话题，中文搜索已覆盖英文源的**转述+解读**，可达 **95%+ 信息完整度**。

## 二、执行模式

### 模式 A：B2B 话题（推荐·已有标准化模板）

直接执行 `references/b2b_topic_china_perspective.md` 的 **8 组中文关键词**：

```
# 第 1 组：政策驱动
WebSearch(query="工信部/发改委/国务院 [话题关键词] 数字化转型 2026")

# 第 2 组：大厂路径
WebSearch(query="阿里 通义千问 字节 火山引擎 华为 企业AI 部署 2026")

# 第 3 组：制造业实证
WebSearch(query="美的 海尔 三一重工 比亚迪 智能工厂 AI 智能体 2026")

# 第 4 组：咨询业
WebSearch(query="普华永道 德勤 毕马威 安永 AI转型 中国 咨询 2026")

# 第 5 组：路径对比
WebSearch(query="中美 AI 路线 对比 商业模式 2026")

# 第 6 组：市场份额
WebSearch(query="字节 阿里 腾讯 MaaS 市场份额 调用量 2026")

# 第 7 组：基础设施
WebSearch(query="阿里 字节 腾讯 AI 资本开支 算力 2026")

# 第 8 组：竞争/估值
WebSearch(query="OpenAI 估值 中美 AI 股价 2026")
```

> 这 8 组本身就是**全信号覆盖结构**——政策层+厂商层+案例层+对比层+规模层+基础层+竞争层——不需要英文搜索补充。

### 模式 B：非 B2B 话题（自设计关键词）

按锚点种子清单自行设计 **6-8 组**关键词：

1. **锚点核心**（2 组）：话题主体+核心概念，一组中文一组英文
2. **关联信号**（1-2 组）：锚点的竞争对手/平行事件/上下游
3. **对立/争议**（1 组）：反方观点/批评/质疑
4. **中国视角**（1 组）：中文受众共鸣点（政策/本土案例/中国厂商）
5. **发散/类比**（1 组）：跨领域规律/历史先例

## 三、验证规则

启动中文搜索主源模式后，**前 3 组采集完必须验证**：

| 检查项 | 标准 | 不达标动作 |
|--------|------|-----------|
| 锚点核心信号命中 | ≥ 3 个独立信源（不同媒体） | 调整关键词重试 |
| 核心数字可交叉验证 | 至少 2 个信源给出同一数字 | 标注"待多源验证" |
| 中国视角有独立信源 | ≥ 1 个中文独有素材 | 追加 1 组中文关键词 |
| 对立/争议有信源 | ≥ 1 个反方观点 | 追加 1 组争议关键词 |

**3 组验证通过 → 确认主源模式有效 → 继续执行剩余 5 组。**

## 四、与其他降级路径的关系

```
WebSearch 故障检测
    ├── WebSearch 挂了但 WebFetch 可用
    │   → 按 references/brave-mcp-degraded-recipe.md 执行（WebFetch 为主 + 中文搜索为辅）
    │
    └── WebSearch 挂了 + WebFetch 也不可用
        → 按本文件执行（中文搜索主源模式）
            ├── B2B 话题 → 模式 A（8 组标准化）
            └── 非 B2B 话题 → 模式 B（6-8 组自设计）
```

**关键原则**：不要等——连续 5 次失败后直接切中文搜索主源，不要反复重试。

## 五、局限性（诚实标注）

| 信号类型 | 中文搜索覆盖 | 缺口 |
|---------|:--:|------|
| 企业官方公告 | 90%+（中文媒体转述） | 原始英文 PDF 全文 |
| 学术论文原文 | 60-70%（摘要级） | 方法论/数据集细节 |
| Substack/博客长文 | 30-40%（偶尔有转述） | 作者原话/完整论证链 |
| 英文社区讨论（HN/Reddit/X） | 10-20% | 几乎不覆盖 |
| 付费墙媒体（Bloomberg/WSJ） | 50%（财经媒体转述） | 原文独家数据 |
| 中国本土新闻 | 95%+ | 基本全覆盖 |

> **对策**：对 P0 核心信源（如 MIT NANDA 原文 PDF），标注"⚠️ 待搜索恢复后补采原文"。
