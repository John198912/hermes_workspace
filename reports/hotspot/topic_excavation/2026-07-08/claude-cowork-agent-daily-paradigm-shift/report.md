### 表2：Claude Cowork 使用数据全景（1.2M 会话，2026.5.11-31）

| 类别 | 占比 | 典型任务 | 受众角色 |
|------|:----:|---------|---------|
| **Business Process & Operations** | **33.4%** | 整合散落更新为统一报告、搭建入职清单、对账表格 | 财务/HR/行政 |
| **Content Creation & Copywriting** | **16.4%** | 草稿、PPT、社媒帖子、提案 | 营销/管理/公关 |
| Software Development | 8.7% | 代码编写 | 开发者 |
| DevOps & Infrastructure | 7.0% | 运维 | DevOps |
| Research & Intelligence | 6.4% | 研究、情报分析 | 分析师 |
| Data Analysis & BI | 5.8% | 数据分析、商业智能 | 数据分析师 |
| Document Processing | 4.1% | 文档处理与提取 | 法律/合规 |
| Sales & Revenue Operations | 4.0% | 销售运营 | 销售 |
| Personal Assistance | 3.8% | 个人助理 | 个人用户 |
| Education | 2.4% | 教育 | 学生/教师 |
| Meeting Intelligence | 1.8% | 会议纪要 | 管理者 |
| 其他（8 个类别） | <4% each | 法律/客服/医疗等 | 各专业角色 |

**关键反直觉发现：**
- **91.3% 的 Cowork 使用与编码无关**——这与"AI Agent = 编码助手"的行业叙事完全相反
- 前两大类别（业务流程+内容创作）合计占 **49.8%**——接近一半的使用是在"工作中的工作"（the work around the work）
- 编码仅 8.7%——AI Agent 的真正价值不在替代程序员，而在替代"每个人都在做但没人说那是本职工作"的碎片化行政劳动

**数据方法说明（来自 Anthropic 官方）：**
- 采样方式：rate-capped（固定每小时最大采样数），非比例采样——数字是"采样会话中的占比"非"绝对流量占比"
- 分类方式：20 类别自动分类系统，按"工作类型"非"岗位名称"分类
- 限制：无独立"营销/财务/HR"类别——这些被吸收进"业务流程"大类，可能部分解释其 33.4% 的高占比
- ~5% 会话为个人非工作用途

### 表3：Claude Cowork 云化的三大技术突破

| 突破 | 之前 | 之后 | 用户体感 |
|------|------|------|---------|
| **Cloud VM 后台运行** | 任务在本地电脑上跑，合上笔记本就停 | 任务在 Anthropic 云端 VM 上跑，电脑关了 AI 继续工作 | "我睡觉，AI 加班" |
| **跨设备无缝同步** | 桌面 App 是唯一入口 | 桌面启动→手机查看进度→Web 端取结果 | "AI 跟着我走，不是跟着电脑走" |
| **定时任务脱机执行** | 必须设备在线 | 设定 6AM 任务→AI 自动跑邮件/新闻/文档→草稿等你审阅 | "早上起来，工作已经做好了" |

**人机协作模式：** Claude 在需要人类决策时（如"是否发送这封邮件？"）会推送通知到手机——**"Nothing is shipped or finalized until the human reviews it."** 这是 Anthropic 刻意强调的安全边界。

### 表5：范式转移的三个层次

| 层次 | 旧范式 | 新范式 | 转折标志 |
|------|--------|--------|---------|
| **交互模式** | "打开 App → 输入 Prompt → 等回复 → 关闭 App" | "派任务 → 去干别的 → 手机收到通知 → 审阅结果" | Cowork 跨设备+Cloud VM |
| **使用场景** | "编码助手"（开发者专用） | "行政同事"（所有人的日常） | 91.3% 非编码数据 |
| **时间关系** | 同步（你在电脑前，AI 才工作） | 异步（AI 在你离线时持续工作） | 定时任务 + 后台运行 |

## Layer 2 文章大纲 + 素材填充

### 控制性理念

### 推荐叙事结构：RIVET + 三层递进（事件→数据→含义）

#### R — Rupture（打破平衡）

**素材填充**：
- 1月→7月时间线（表 1）
- SaaSpocalypse 案例（类型 4 案例 3）

#### I — Illuminate（照亮盲区·三层递进）

**盲区 1：AI Agent 的真实用户不是程序员——是"每个人"**

- 行业叙事：AI Agent = 编码助手（Copilot、Claude Code、Cursor）
- 真实数据：91.3% 的 Cowork 使用与编码无关
- 第一大用途：业务流程（33.4%）——对账、做报告、建清单
- 第二大用途：内容创作（16.4%）——写 PPT、社媒帖子、提案
- 核心洞察：**AI Agent 在替代的不是"专业技能"，而是"谁都逃不掉的碎片化行政劳动"**——Anthropic 称之为"the work around the work"

**盲区 2（第二层·技术突破）：AI 从"工具"变成了"员工"——三个关键变化**

- 变化一：**Cloud VM 后台运行**——以前：AI 在你电脑上跑，合上就停。现在：AI 在云端跑，你关电脑它照干
- 变化二：**跨设备无缝同步**——以前：只能坐在电脑前用。现在：桌面启动→手机看进度→Web 取结果
- 变化三：**定时任务脱机执行**——以前：你必须在场。现在：设定 6AM 任务→AI 自主执行→草稿等你审阅
- 核心隐喻：**"你的 AI 不下班了"**——这不是修辞，这是产品事实

**盲区 3（第三层·竞争格局）："Agent 控制权"的战争——谁拥有"工作发生的地方"**

- Anthropic：Cowork（个人）+ Tag（团队）——钳形战略
- OpenAI：Workspace Agents（团队共享）+ Codex（通用化）
- Microsoft：Agent 365——把 Agent 当员工管理（独立身份/权限/生命周期）
- Google：Gemini Spark——搜索+办公生态
- 核心洞察：战争不是"谁的模型更好"——是"谁的 Agent 成为你日常工作的默认界面"

#### V — Validate（验证处境）

**数据铁三角**：
- 120 万条会话 + 91.3% 非编码——AI Agent 的重点不是代码，是"工作中的工作"
- 前两大类别占 49.8%——AI 在替代"碎片化行政劳动"，不是"核心专业技能"

**竞争矩阵验证**：
- 每个巨头都在把 Agent 从"工具"推向"员工"
- Microsoft 的 Agent 365 最激进——直接给 Agent 分配"员工身份"和"权限"
- 但最成功的 Agent 部署案例是 KPMG 27.6 万员工——说明 Agent 确实在进入"日常化"
