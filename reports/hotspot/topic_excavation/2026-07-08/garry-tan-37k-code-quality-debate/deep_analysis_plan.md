> 模型：D（观点/批判型）——多视角三角 + 反直觉翻转
> 控制性理念：「AI让你产出更快，但不一定让你产出更好。判断力才是稀缺品。」

## 一、七段式结构设计

### 引子：场景爆破——"他吹了37K，然后有人去看了"

**节奏**：⚡ 快速，高密度

**叙事结构**：
1. 钩子：Garry Tan在X上发帖——"agentic AI让我每天部署37K行代码，72天连续发货，5个项目，还在加速"
2. 数据冲击：波兰开发者Gregorein去看了。首页加载169次请求、6.42MB。HN首页——YC自己运营的——7次请求、12KB。
3. 荒诞展开：28个测试文件直接暴露给用户。78个JS控制器下载了但页面不用。Logo有8种格式含一个0字节损坏版。520KB富文本编辑器加载在只读页面上。47张图片空alt属性。
4. 反常识张力建立："YC投了4000多家创业公司，教创始人'快速迭代'。但YC的CEO用AI造出来的东西，被一个独立开发者用半天时间拆了个底朝天。"
5. 点题：这不是一个八卦——这是一个信号。AI正在让"做更多"和"做更好"变成两件完全不同的事。

**关键数据呈现**：
| 对比项 | Tan的AI网站 | HN（YC运营） | 倍数 |
|--------|-----------|------------|------|
| 首页请求 | 169次 | 7次 | 24x |
| 页面大小 | 6.42MB | 12KB | 535x |
| 总代码量 | 78,400行 | — | — |

### 第一部分：逐层拆解——"这不是AI的错，这是把AI当KPI机器的错"

**节奏**：🚶 中速→🐢 渐慢，四层递进

#### 第一层：技术层——代码臃肿的"七宗罪"
- 28个测试文件暴露 → 没有"生产环境vs开发环境"的概念
- 78个未使用控制器 → AI不知道"这个页面需要什么"
- 8种Logo格式含损坏版 → AI不知道"哪个能用"
- 2MB未压缩PNG → AI不知道"用户体验"
- 520KB编辑器在只读页面 → AI不知道"上下文"
- **核心洞察**：AI不是"写错了"——它是"不知道自己在写什么"。它有代码能力，没有产品判断。

#### 第二层：指标层——"考核什么，就得到什么"
- 引用Goodhart's Law：当一个指标变成目标，它就不再是好的指标
- LOC（代码行数）是最经典的坏指标——"少即是多"是软件工程的铁律
- 但AI时代出现了新变体：Tokenmaxxing——把消耗token量当生产力
- HN评论#65 zerof1l的金句："就像你绕了10000步才走到500步之外的商店，然后吹嘘自己走了10000步"
- **核心洞察**：Tan没有恶意——他只是被自己的KPI欺骗了。37K行/天这个数字本身就说明他根本不知道什么才值得量。

#### 第三层：治理层——"AI比审查快→那就别审查了"
- Fast Company的关键引语："AI让你生成代码的速度超过任何人类能审查的速度——Garry Tan的答案似乎是'那就别审查了'"
- 类比：HN评论#97 chrisandchris——医生试了再说/桥梁建了再修/汽车刹车上路再测。这些行业这样做会被吊销执照。但软件行业正在接受"ship first, fix later, never fix"
- Tan的辩护逻辑："agent观察使用数据后会自动修正这些错误"——但78,400行代码已经上线了，用户在访问，测试文件在泄露
- **核心洞察**：不是"AI写不好代码"——是"AI让跳过审查看起来合理"

#### 第四层：价值层——"更重要的是：他到底造了什么？"
- HN评论#86 astonex："37K行/天，185K/周，到底造了什么？我没看到任何实际产出。"
- 对比：不是"AI写代码"vs"人写代码"。是"AI写代码造出了什么"vs"人写代码造出了什么"。
- 经济学的经典问题：生产力=产出/投入。如果投入是"37K行代码"，产出是什么？一个6.42MB的首页？
- **核心洞察**：这场辩论的深层问题不是"AI代码质量好不好"——是"AI增加的是什么？是生产力还是生产力幻觉？"

### 第二部分：揭示推力——"为什么是现在？为什么是Tan？"

**节奏**：前半快（推力），后半慢（机制）

#### 推力1：AI生产力叙事需要"英雄"
- 2026年AI行业需要新叙事——"AI替代工作"的恐惧需要被"AI增强人类"的神话中和
- 37K行/天是这个叙事的最新版本——"你看，AI不是来替代你的，是让你变成超级个体"
- 问题：这个"超级个体"的例子恰好证明了相反的东西

#### 推力2：YC的"增长即正义"文化
- YC的DNA是"快速迭代、快速发布、快速失败"
- Facebook的"move fast and break things"被证明有效——但同时也留下了大量技术债
- "先盈利，后正确"——这在某些场景下有效，但被当作普适法则就很危险

#### 推力3：AI工具公司需要"证明ROI"
- Cursor $2B ARR，GitHub Copilot 20M用户——AI编码工具市场$7-10B
- 这些公司需要"AI让开发者10x生产力"的叙事来维持估值
- 37K行/天是这种叙事的极端版本——但它被拆穿的速度也是极端的

#### 心理机制：为什么我们相信"37K行"？
- **锚定效应**：听到"37K"这个数字，大脑自动锚定"大量=高效"
- **光环效应**：YC CEO → 权威 → 他说的话可信
- **确认偏误**：用AI的人希望相信"AI=生产力"——37K行/天证实了这个信念
- **社交证明**：72天连续发货→听起来像真的→没人去验证

### 第三部分：结构归因——"不是你的焦虑出了问题"

**节奏**：🔭 视野拉升，从个人转向时代

#### 集体分离仪式
- 技术社区正在经历一次"AI生产力叙事"的集体分离——从"AI=10x"的旧信念中分离
- 这个分离是痛苦的：没有AI的人焦虑被淘汰，用AI的人焦虑产出质量
- Tan的故事恰好是两种焦虑的交汇点——"AI让你做更多，但更多不等于更好"

#### 两个时钟的冲突
- 技术时钟（AI进步速度）以月为单位。人类时钟（判断力培养）以年为单位。
- 37K行/天是技术时钟的产物。代码审查需要的人类判断力是另一个时钟。
- 两个时钟从来不对齐——这不是你的问题。

#### 场域错位
- Tan的"37K行/天"在YC CEO场域是英雄叙事。在开发者场域是笑话。
- 当两个场域的"好"的定义完全不同，沟通注定失败。
- 这不是谁对谁错——是两个世界在说不同的语言。

### 第四部分：反刍时刻——"先停一下。代码质量不是重点。"

**节奏**：🛑 停顿，最长留白

**重命名情绪**：
- "AI让我焦虑" → "AI让我看清什么才是真正重要的"
- "AI产出太快我跟不上" → "AI产出太快，所以判断力变成了稀缺品"
- "我不会写代码怎么办" → "你不会写代码，但你会判断什么值得写——这是AI做不到的"

**反直觉翻转（全篇情感转折点）**：
> "37K行代码被拆穿——这不是AI的失败，这是AI最诚实的时刻。它告诉你：AI能写代码，但不能判断。能产出，但不能选择。能加速，但不能校准方向。"
> 
> "判断力不是AI时代的'附加技能'——它是AI时代唯一不可被替代的资产。不是因为AI太弱——是因为AI太强了。强到你不加判断，它会把你淹没在代码的海洋里。"

**减速标记**：
```
（暂停一下。）

前三层是你能看到的——代码臃肿、指标失效、审查缺失。它们真实、重要、但不是全部。

这一层才是我真正想说的：37K行代码不是问题——它是答案。它告诉你，当AI可以无限产出时，稀缺的不是产出能力——是判断"什么值得产出"的能力。

而那个判断力——你已经有。只是你一直以为它不值钱。
```

### 第五部分：ZPD行动框架——"在'更多'的时代，做'更少'的人"

**节奏**：🚶 从慢到稳，邀请句式

#### 行动一：审计你的"37K行"
- 不是让你去看代码——是让你审视"AI帮你做的事"
- 问自己：AI帮我产出了更多，但产出的是什么？有多少是"测试文件暴露给用户"级别的无用功？
- 最小行动：这周选一个AI帮你完成的任务，手动审查一遍——不是为了改，是为了"看"

#### 行动二：建立你的"判断过滤器"
- 三条铁律：
  1. **AI产出前，你先写一句话**：这个产出应该解决什么问题？——如果AI的产出没解决这个问题，它就是垃圾，不管它多长
  2. **AI产出后，你问三个问题**：这是必要的吗？这是最简的吗？这是用户可以用的吗？
  3. **如果你不知道答案，AI也不知道**——在你不懂的领域，AI是"每门课得D的学生"，不是"每门课得A的教授"

#### 行动三：从"AI使用者"升级为"AI导演"
- 低级用法：AI写代码，你复制粘贴（=Tan的水平）
- 中级用法：AI写代码，你审查修改（=大部分开发者的水平）
- 高级用法：你定义"什么值得写"，AI写，你判断"写得对不对"（=超级个体的水平）
- 不是"你不会写代码所以你得用AI"——是"你会判断，所以AI是你的杠杆"

#### 行动四：把你的"判断力"变成产品
- AI写代码→代码不值钱。AI写文章→文章不值钱。AI做设计→设计不值钱。
- 但你的判断力——你选择做什么、不做什么、怎么做——这是AI无法替代的。
- 把这个判断力变成你的产品、你的服务、你的内容。
- 不是"AI帮你做"——是"你告诉AI做什么，然后你检查它做得对不对，然后你为结果负责"

### 尾声：螺旋回环——"下一篇我们聊聊：AI时代的'判断力'到底是什么？"

**节奏**：🔄 回环，开放式邀请

> "37K行代码不是终点——它是一个问题。这个问题不是'AI能写多少代码'——是'在AI可以无限产出的世界里，你选择产出什么？'"
> 
> "Garry Tan选择了产出6.42MB的首页。Gregorein选择了产出一份48小时的审计报告。后者被分享了110次，被97个人讨论了，被Fast Company报道了。"
> 
> "两个人的AI都用得一样好。但一个人的判断力让他的产出变成了笑话，另一个人的判断力让他的产出变成了新闻。"
> 
> "下一篇，我们聊聊：AI时代的'判断力'到底是什么？怎么训练？怎么证明？"
> 
> "在那之前——下次AI帮你做了一件事，别急着开心。先问自己：这是我想要的吗？还是这只是AI能给的？"
